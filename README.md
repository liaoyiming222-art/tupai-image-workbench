# 图派 · AI 批量作图工作台

基于 RunningHub 的 Windows 本地 AI 批量作图工具。读取需求文件夹，把每条需求列为任务，自动处理原图与参考图的编号对应，生成结果回存各自的 `AI` 子文件夹。

作者：[liaoyiming222-art](https://github.com/liaoyiming222-art)

## 两个版本

| 版本 | 用途 | 启动方式 |
| --- | --- | --- |
| 本地版 | 真实目录读取、RunningHub 生图、结果回存 | 双击“图派启动器.exe”或桌面“图派”快捷方式 |
| 在线演示版 | 示例导入、编号映射、模拟队列及预设结果展示 | [打开在线演示](https://tupai-image-workbench.vercel.app/) |

在线演示仅发布 demo/ 下的静态文件，不读取个人素材、不收集真实 Key、不调用真实生图接口；刷新或重置后恢复示例。真实作图请使用本地版。

## 功能

- 批量导入需求文件夹，支持上级目录扫描和多条路径。
- 一个 RunningHub API Key，调用 Nano Banana 2 和 GPT Image 2.0。
- 按处理分类自动选择模型，也可手动指定本次使用的模型。
- 自动转换提示词中的图片编号，保持图片输入顺序与文字引用一致。
- 缓存缩略图、按需加载、每页 50 条任务；可关闭缩略图。
- 队列暂停、失败恢复、执行记录、结果居中预览。
- 结果自动保存并增加版本号，不覆盖已有图片。

## 环境与启动

完整功能面向 **Windows 10/11、Node.js 22 或更新版本**。无第三方 npm 依赖，无需配置模型接口路径。

```bash
git clone https://github.com/liaoyiming222-art/tupai-image-workbench.git
cd tupai-image-workbench
npm start
```

打开 [http://127.0.0.1:5137/](http://127.0.0.1:5137/)。

Windows 推荐从 [Releases](https://github.com/liaoyiming222-art/tupai-image-workbench/releases/latest) 下载本地版并解压，安装 Node.js 22 或更新版本后双击 `图派启动器.exe`。启动器会检测已有服务、后台启动并等待就绪，然后打开独立的 Edge 应用窗口（找不到 Edge 时使用默认浏览器），不需要打开 Codex 或手动输入地址。

从源码使用时，双击 `启动工作台.cmd`，会在首次启动时用 Windows .NET Framework 编译启动器。停止时双击 `停止工作台.cmd`；这两个主入口均不调用 PowerShell。原有 `.ps1` 文件仅作兼容保留。首次使用目录组件时，通过 Windows 自带 .NET Framework 编译器编译 `native/FolderPicker.cs`。

生成带图标的启动器：`npm run build:launcher`。创建桌面快捷方式：双击 `创建桌面快捷方式.cmd`，或在项目目录运行 `图派启动器.exe --install-shortcut`。快捷方式指向项目中的 exe，不要把 exe 单独移出项目目录。首次版本依赖本机 Node.js，未捆绑运行环境。

关闭应用窗口不会立即结束本地服务；停止服务使用停止入口，有活动任务时会提示先等待当前任务完成。启动日志在 `.local/service.log`，启动器错误在 `.local/launcher.log`。

终端启动可使用 `Ctrl+C` 停止。重启后保留记录，队列默认暂停。端口冲突时可通过环境变量 `PORT` 指定其他端口。

## 需求文件夹格式

**一个需求文件夹对应一份 `作图需求.json` 和一套图片编号。** 不需要图片清单或原始备份目录。

```text
需求文件夹/
├─ 原图/
│  ├─ 图片1.jpg
│  ├─ 图片2.png
│  └─ 图片3.webp
├─ AI/
└─ 作图需求.json
```

- `原图/`：放全部待处理图和参考图，二者使用同一套编号。
- 图片命名为 `图片1.jpg`、`图片2.png` 等，保留真实扩展名；支持 JPG、JPEG、PNG、WebP。
- 同一需求文件夹中，每个序号只能对应一张图片，不能同时有 `图片1.jpg` 和 `图片1.png`。编号可以不连续。
- `AI/`：保存生成结果，可以提前创建为空；缺失时工具会在执行前创建。
- JSON 使用 **UTF-8 编码**；文件名必须是 `作图需求.json`。
- 不同需求文件夹可重复使用 `图片1`、`T001` 等编号。

### 作图需求 JSON 示例

下面两条任务会分别生成一张图片，可共用同一张原图或参考图：

```json
{
  "作图需求": [
    {
      "任务编号": "T001",
      "处理分类": "局部重绘-Gemini",
      "要处理的图片": "图片1",
      "参考图编号": ["图片3"],
      "具体要求": "保持@图片1的原视角，将桌子右侧的窗帘替换为白色，窗帘形状参考@图片3。",
      "输出比例": null
    },
    {
      "任务编号": "T002",
      "处理分类": "局部重绘-gpt",
      "要处理的图片": "图片1",
      "参考图编号": [],
      "具体要求": "扩图，保证@图片1中的桌子在画面中心，保持原视角不变。",
      "输出比例": "16:9"
    }
  ]
}
```

### 六个字段

每条任务固定包含以下六个字段，不增加额外字段：

| 字段 | 格式 | 规则 |
| --- | --- | --- |
| 任务编号 | 字符串，如 `T001` | 在当前 JSON 中唯一；只使用字母、数字、短横线、下划线，最长 80 个字符 |
| 处理分类 | 字符串 | 仅 `局部重绘-Gemini` 或 `局部重绘-gpt` |
| 要处理的图片 | 字符串，如 `图片1` | 主图编号，不写扩展名 |
| 参考图编号 | 字符串数组 | 如 `["图片2", "图片3"]`；无参考图写 `[]` |
| 具体要求 | 非空字符串 | 简述处理要求，用 `@图片N` 标注所用图片 |
| 输出比例 | 比例字符串或 `null` | 如 `"4:5"`；无指定比例写 JSON 空值 `null`，不能写字符串 `"null"` 或空字符串 |

主图和参考图必须在“具体要求”中被引用；正文引用的每张图也必须列入主图或参考图。一条任务对应一张输出，要求三张结果时应拆成三条独立任务。

可复制 [JSON 模板](docs/作图需求.example.json)；编辑器校验可参考 [JSON Schema](docs/task.schema.json)。Schema 仅用于编辑器，**不要把 `$schema` 字段加入实际需求文档**。

### 批量需求目录

```text
本批需求/
├─ 需求A/
│  ├─ 原图/
│  ├─ AI/
│  └─ 作图需求.json
└─ 需求B/
   ├─ 原图/
   ├─ AI/
   └─ 作图需求.json
```

选择“本批需求”并启用“扫描子文件夹”，或者粘贴多个需求目录的完整路径，每行一条。原图目录、AI 目录和隐藏目录不会继续扫描。

仓库附带两个纯色图片示例，点击页面“载入示例”即可检查导入与编号转换；示例不能用于评价真实产品图效果。Git 不保存空文件夹，示例 `AI/` 中的 `.gitkeep` 仅用于保留目录。

## 使用流程

1. 在 **API 设置** 中保存一份 RunningHub API Key。
2. 选择需求目录，点击 **扫描并导入**。
3. 选择 **按处理分类自动选择**、**Nano Banana 2** 或 **GPT Image 2.0**。
4. 打开任务详情，核对素材编号映射和发送提示词。
5. 执行选中任务或全部就绪任务，查看运行记录和生成结果。

默认映射：

| 处理分类 | 模型 |
| --- | --- |
| 局部重绘-Gemini | Nano Banana 2 |
| 局部重绘-gpt | GPT Image 2.0 |

手选模型只覆盖新提交任务的模型选择，不修改原 JSON 的分类。已入队任务固定使用入队时的模型、参数和凭据。

## 图片编号如何对应

假设文件夹中的主图为 `图片1`、参考图为 `图片3`，本次只发送这两张图：

| 文件夹编号 | 模型输入 |
| --- | --- |
| 图片1 | 第 1 张，提示词引用 @图片1 |
| 图片3 | 第 2 张，提示词引用 @图片2 |

工具先确定“主图在前、参考图按数组顺序”的输入序列，再一次性重写提示词引用，上传也使用同一序列。原始 JSON 和原图保持原样。

## 比例、限制和结果

- `输出比例: null` 时，不发送比例参数、不补充比例指令，由模型自适应。
- 指定比例时按需求发送；模型不支持该比例时会提示并阻止提交。
- 两模型最多输入 10 张图；Nano 单图上限 30MB，GPT 为 50MB。
- 最终提示词长度为 1–20000 字符，默认分辨率 `1k`。
- 结果命名为 `AI/T001_01.jpg`、`AI/T001_02.png` 等，扩展名依据实际输出格式，版本号自动递增。
- 暂停只停止新任务启动，已提交任务继续查询和回存。
- 有远程 taskId 的失败任务优先继续查询/下载；提交结果不确定时不会自动重发。

## 本地数据与 API Key

程序仅监听本机地址。原图在点击执行后上传至 RunningHub，生成可能产生 RunningHub 费用。

API Key、任务记录、缩略图和本机组件保存在 `.local/`，不会写入需求目录。Key 采用 AES-256-GCM 加密；本机随机加密密钥也位于 `.local/`，同时拥有配置和密钥文件的人仍可解密，因此不要分享该目录。

`.gitignore` 已排除本机状态、凭据、日志、截图及 AI 生成结果。仓库示例图片由程序生成，不含个人素材。

## 开发与验证

```bash
npm test
```

测试模拟 RunningHub 上传、提交、查询与下载，不使用真实 Key、不消耗生成额度。GitHub Actions 在 Windows 上检查 Node.js 22 和 24。

```text
lib/         需求解析、编号映射、模型调用、凭据与目录组件

tests/       自动化测试
```

演示版构建：`npm run build:demo`；检查生成文件同步：`npm run check:demo`；本地演示预览：`npm run preview:demo`。Vercel 使用 demo 作为根目录，Other 预设，输出 public，无服务端函数。演示与本地版复用界面、模型目录和编号映射代码，只有数据访问层不同。
