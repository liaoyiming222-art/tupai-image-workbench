# 本地工作台 · 当前实现方案

## 本地与在线演示分离

- 本地版保留 server.mjs、真实目录访问和 RunningHub 调用。Windows 原生启动器自动启动独立后台服务、等待健康检查、打开 Edge 应用窗口，支持桌面快捷方式和停止服务。
- Vercel 仅部署 demo/public 中的纯静态文件，项目根目录设为 demo，Other 预设、无构建/安装命令，不运行 server.mjs。
- public/app.js、样式、图标、模型目录与纯函数编号映射共用；本地 transport 使用本机 API，演示 transport 完全使用内存模拟，无网络请求。
- 演示版使用自制 SVG 示意素材、虚拟目录与预设结果，支持模拟队列、失败恢复、虚拟配置和一键重置，醒目标注为演示。
- 真实 Key、任务记录、业务素材、CLI 登录文件及缩略图仍仅保存在本机，不进入部署包。

- 批量任务页：顶部概要统计；中部导入需求、选择生成模型两块；下部任务表格与执行操作。支持读取多路径、递归扫描、导入去重、筛选、任务详情、执行副本编辑、批量队列、暂停恢复。主图缩略图在本机生成并缓存，按需加载，每页最多50条，可关闭预览；状态轮询不重复替换相同的列表内容。窄屏按顺序纵向排列，表格横向滚动。
- API 设置页：一个共享 RunningHub API Key 输入框、显示/隐藏及保存操作。右侧简要说明自动分类映射和手动模型选择。无节点、接口路径、参数 JSON 等配置。凭据使用本机随机密钥进行 AES-256-GCM 加密。
- 运行记录页：执行状态、最终提示词、编号映射、taskId、保存位置、恢复查询或下载。

## 执行边界

1. 原 JSON 和素材不改写。页面编辑只影响工具中的执行副本。
2. 单任务图片按主图、参考图顺序去重，先确定输入序列，再一次性转换所有 @图片N。上传顺序和文字映射使用同一序列。
3. 模型选择默认为按分类自动：局部重绘-Gemini → Nano Banana 2，局部重绘-gpt → GPT Image 2.0。也可统一指定 Nano 或 GPT 执行新任务。Key 用于验证同一账户，选择模型实际选择不同提交接口路径；上传和查询仍使用共享 Key。任务入队后冻结模型、接口参数及凭据，后续切换不影响旧任务，不改写原 JSON 分类。
4. null 比例不发送比例参数，由模型自适应。
5. 保存远程任务编号后轮询；输出下载成功才算完成。
6. AI 子文件夹内按任务编号加版本保存，不覆盖结果。所有任务归属于原文件夹。
7. 有 taskId 或结果 URL 的失败任务优先恢复，不重复提交；无法确定提交结果时进入待核对。
8. 保留“选择文件夹”：采用 Windows 现代文件对话框的目录选择模式，含地址栏、搜索及快捷位置，返回真实目录路径，不使用 PowerShell。打开需求和AI目录直接使用Windows文件夹关联，失败明确提示。完整结果使用独立居中预览页。手动路径输入和批量目录扫描继续支持。
9. 按实际所选模型检查图片数、文件大小、提示词长度和比例：均最多 10 图；Nano 单图 30MB，GPT 50MB；提示词 1–20000 字符；不支持的比例拒绝提交。默认分辨率 1k。
10. 旧版相同 Key 自动合并；不同 Key 不代用户选择，提示重新填写共享 Key，历史远程任务仍保留原凭据恢复查询。页面仅显示“已保存”，不将其视为真实调用验证成功。

## 本次交付范围

Windows 本机、图片生成、RunningHub 单平台。不发布网站，不要求平台改变既有六字段 JSON，不增加原始备份或图片清单。
