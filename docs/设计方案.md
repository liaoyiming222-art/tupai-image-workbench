# 本地工作台 · 当前实现方案

## 本地与在线演示分离

- 本地版保留 server.mjs、真实目录访问和 RunningHub 调用。Windows 原生启动器自动启动独立后台服务、等待健康检查、打开 Edge 应用窗口，支持桌面快捷方式和停止服务。
- Vercel 仅部署 demo/public 中的纯静态文件，项目根目录设为 demo，Other 预设、无构建/安装命令，不运行 server.mjs。
- public/app.js、样式、图标、模型目录与纯函数编号映射共用；本地 transport 使用本机 API，演示 transport 完全使用内存模拟，无网络请求。
- 演示版使用自制 SVG 示意素材、虚拟目录与预设结果，支持模拟队列、失败恢复、虚拟配置和一键重置，醒目标注为演示。
- 真实 Key、任务记录、业务素材、CLI 登录文件及缩略图仍仅保存在本机，不进入部署包。

- 批量任务页：顶部概要统计；中部导入需求、选择生成模型两块；下部任务表格与执行操作。支持读取多路径、递归扫描、导入去重、筛选、任务详情、执行副本编辑、批量队列、暂停恢复。主图缩略图在本机生成并缓存，按需加载，每页最多50条，可关闭预览；状态轮询不重复替换相同的列表内容。窄屏按顺序纵向排列，表格横向滚动。
- API 设置页：一个共享 RunningHub API Key 输入框、显示/隐藏及保存操作。右侧简要说明自动分类映射和手动模型选择。无节点、接口路径、参数 JSON 等配置。凭据使用本机随机密钥进行 AES-256-GCM 加密。
- 运行记录页：执行状态、最终提示词、编号映射、taskId、保存位置、恢复查询或下载。

## 执行边界

1. 原 JSON 和素材不改写。页面编辑只影响工具中的执行副本。
2. 单任务图片按主图、参考图顺序去重，先确定输入序列，再一次性转换所有 @图片N。上传顺序和文字映射使用同一序列。
3. 模型选择默认为按分类自动：局部重绘-Gemini → Nano Banana 2，局部重绘-gpt → GPT Image 2.0。也可统一指定 Nano 或 GPT 执行新任务。Key 用于验证同一账户，选择模型实际选择不同提交接口路径；上传和查询仍使用共享 Key。任务入队后冻结模型、接口参数及凭据，后续切换不影响旧任务，不改写原 JSON 分类。
4. null 比例不发送比例参数，由模型自适应。
5. 保存远程任务编号后轮询；输出下载成功才算完成。
6. AI 子文件夹内按任务编号加版本保存，不覆盖结果。所有任务归属于原文件夹。
7. 有 taskId 或结果 URL 的失败任务优先恢复，不重复提交；无法确定提交结果时进入待核对。
8. 保留“选择文件夹”：采用 Windows 现代文件对话框的目录选择模式，含地址栏、搜索及快捷位置，返回真实目录路径，不使用 PowerShell。打开需求和AI目录直接使用Windows文件夹关联，失败明确提示。完整结果使用工具内可关闭预览弹窗，支持缩放、原尺寸与拖动。手动路径输入和批量目录扫描继续支持。
9. 按实际所选模型检查图片数、文件大小、提示词长度和比例：均最多 10 图；Nano 单图 30MB，GPT 50MB；提示词 1–20000 字符；不支持的比例拒绝提交。默认分辨率 1k。
10. 旧版相同 Key 自动合并；不同 Key 不代用户选择，提示重新填写共享 Key，历史远程任务仍保留原凭据恢复查询。页面仅显示“已保存”，不将其视为真实调用验证成功。

## 本次交付范围

Windows 本机、图片生成、RunningHub 单平台。不发布网站，不要求平台改变既有六字段 JSON，不增加原始备份或图片清单。


## 本地版批次与数据看板优化（2026-11-02）

- 一次成功扫描形成一个导入批次，默认显示最新批次，可切回历史；旧数据归入历史导入。任务按首次导入时间倒序，旧数据使用已有 importedAt。
- 本批列表和统计统一范围；移除只更新批次成员，保留任务底层记录、执行历史和磁盘文件。整批操作跳过排队及执行中任务。
- 运行记录后端基于全量历史筛选分页，每页50条；详情可单独读取，不受状态快照最近300条限制。
- 看板显示成功保存图片数、预计节约时间、提交次数、执行成功率；日/月趋势与模型分布跟随所选时间，12个月汇总使用全部记录。单图节约分钟数可调整并持久保存。
- 产出按执行创建日期归属，使用北京时间；新记录在创建请求前计数，恢复查询和下载不计新提交。旧记录提交次数依远程编号估算，明确标注。
- 重新定位按整个需求目录进行预检和确认；验证编号、内容、素材与结果可访问性。更新任务身份、批次引用和执行关联，保留原执行路径，不修改执行提示词与模型。活动任务和目标冲突阻止定位。
- 本次只更新本地 public 与服务端，demo/public 保持原版。未来同步时需同时适配模拟数据接口，暂不运行 build:demo 或 check:demo。


## 后台版本一致性修复

静态页面每次请求读取磁盘文件，而服务端代码在进程启动时加载。仅刷新页面或再次打开启动器，原来会复用旧服务，导致新操作找不到接口。本地公共状态现在返回 apiRevision=2，页面在渲染工作区前验证兼容性。启动器核对协议版本；空闲旧服务通过正常停止接口退出并重新启动，有执行或排队任务时保留服务并提示等待。404接口错误转换为可操作的重启说明。关闭应用窗口仍不等于停止服务。


## 当前导入流程（2026-11-02更新）

- 已删除重新定位需求文件夹的按钮及 /api/relocate 接口，前文关于重新定位的说明作为历史设计记录。
- 待导入清单为空开始；复制多个目录后点击粘贴文件夹或在导入区按Ctrl+V，按需使用原生多选、手动输入路径、移除条目和清空清单。清空清单不影响已导入任务。
- 本地原生组件读取Windows文件列表或多行路径；仅带本机令牌的POST可触发剪贴板读取，不在轮询中读取。去重、普通文件跳过、失效路径标注，点击扫描才创建一个批次。父子目录的重复发现只读取一次。
- 原生组件使用winexe、无隐藏父窗口的Shell多选对话框；支持取消请求，重复请求唤起当前窗口。后台必须运行在正常Default桌面；从Codex隔离桌面启动会明确报错，正常使用桌面启动器。
- 普通Edge网页拖拽目录无法可靠取得原路径，因此本轮不启用名称推测导入；只接受拖入的完整路径文本，目录拖拽缺少路径时提示复制粘贴或选择目录。
- 本地接口协议升为3，启动器、页面与后台已同步；未修改demo/public。
