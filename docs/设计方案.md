# 图派 · 当前实现说明

## 架构与启动

本地版由 server.mjs、lib、public 和 Windows 原生组件组成，Node.js 22 及以上运行，无第三方运行依赖。启动工作台.cmd 编译并启动 native/Launcher.cs；启动器依赖 scripts/boot-local.mjs 启动后台，不能删除该脚本。停止工作台.cmd 安全停止服务。关闭页面不等于停止服务。

在线演示独立部署 demo/public，复用本地界面，通过 demo/src/transport.mjs 在内存中模拟目录、任务、历史和统计。修改共用代码后执行 build:demo 和 check:demo。演示不读取真实目录、不接收真实 Key、不调用付费服务。

## 页面与任务范围

左侧导航保持原设计。批量任务页使用紧凑导入区，统计合并至列表标题，模型选择靠近执行按钮；首页只显示当前导入任务，不提供批次切换或手动路径输入。保留文件夹粘贴、Ctrl+V、原生多选、子目录扫描、去重和失效目录反馈。成功导入后清空待导入清单；失败提示可展开。

一次成功扫描创建导入批次，历史执行在运行记录中查询。新导入清空勾选，全选只选当前页，执行全部就绪针对当前列表。移除只影响列表成员，保留底层记录和磁盘文件，跳过排队及执行中任务。列表每页50条，缩略图按需加载。

运行记录直接展示日期、模型、批次、分类和搜索，后端基于全量历史筛选分页。API设置集中展示共享Key与模型对应关系。看板保留成功出图、节约时间、提交次数和成功率，口径说明及12个月汇总折叠。详情优先显示状态、异常、结果与执行要求，映射及原始要求按需展开。

## 执行与数据边界

- 原始JSON和素材不改写；编辑只影响执行副本。需求格式及约束见README和Schema。
- 主图在前、参考图随后去重，先确定图片输入顺序，再一次性转换引用编号，上传与提示词使用同一映射。
- 默认按分类选择Nano Banana 2或GPT Image 2.0，也可指定新任务模型。入队后冻结模型、参数与凭据，后续切换不改变旧任务。
- 空比例不发送比例参数。图片数量、大小、提示词和比例在提交前按实际模型校验。
- 保存远程任务编号后查询，结果下载成功才算完成。AI目录按编号和版本保存，不覆盖已有图片。
- 有远程编号或结果URL的失败任务优先恢复查询/下载；无法确定提交结果的任务进入待核对，不自动重复提交。
- 一个共享Key在本机加密保存，页面仅显示保存状态，不表示真实调用验证成功。历史任务保留原凭据恢复能力。
- 本机数据、加密密钥、缓存及备份位于.local，不发布或作为普通临时文件清理。目录选择使用Windows原生组件，缺少目录原路径时不猜测路径。
- 页面与后台核对接口版本；旧后台空闲时由启动器正常更新，活动任务存在时提示等待。当前接口协议为3。
- 看板按北京时间及执行创建日期归属产出；旧提交次数可能为估算，界面明确提示。恢复查询和下载不计新提交。

## 验证与维护

运行 npm test、npm run check:demo；原生组件测试串行执行。覆盖编号映射、凭据迁移、恢复下载不重复提交、历史分页、导入去重、列表移除保护及启动器自检，不使用真实Key或付费生成服务。

浏览器适配与素材验收记录见 portfolio-assets/README.md。未穷举所有Windows显示缩放与多显示器组合。已删除重新定位入口及接口，路径失效时不能依赖旧审查记录中的重新定位操作。

旧本地审查原文归档到.local/archive，仅保留有效边界与验证结论在本说明中。正式宣传素材、原始拍摄与可复现排版源文件保留在portfolio-assets。
